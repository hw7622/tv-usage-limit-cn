## v2.8.1-cn：安全复查（不是新功能，是补窟窿）

上线 v2.8.0 后复查了一遍网络层，发现两个真正的漏洞，都已修并真机验证：

| 问题 | 后果 | 修法 |
|---|---|---|
| 登录限流拿 `X-Forwarded-For` 当 key | 客户端随便换这个头 → 限流归零 → 4 位 PIN 在局域网里几秒穷举完；还能灌随机 key 把内存吃满 | 改用 `socket.inetAddress`，表超过 256 条回收 |
| `allowRemote` 写成了「不再限制来源」 | 家长为了用 Tailscale 打开开关，等于把 8080 挂到公网。国内宽带大量下发公网 IPv6，光猫 DMZ 也常见，防护只剩一个 4 位数字 | 改成只在白名单里**追加** CGNAT 与 ULA，**公网永远 403** |

另外三道加固：

- **Host 头必须是 IP 字面量**（或 `localhost` / `*.ts.net` / `*.local`），挡 DNS rebinding ——
  只靠「来源是局域网」挡不住反弹，因为请求确实来自局域网内。
- **CSP**：`default-src 'self'; script-src 'self'; frame-ancestors 'none'`，页面全是拼字符串渲染的，
  万一漏一个 `esc()` 也不至于被执行。
- **20 分钟没人用自动关服务**。家长最容易犯的错不是密码弱，是开完忘了关。

以及两个「家长会困惑」的小毛病：

- 电视上二维码区在服务关闭后留一个白方块 → 现在整块收起。
- 题库矩阵只报「低于 8 道」，把 116 道的五年级英语也说成没问题 →
  增加 `target=150` 档，红/黄/绿三级，「几乎没题」和「撑不住一周」分开报。

答案分布 A/B/C/D = 25/25/25/25%。二年级语文 558 道 ≈ 46 天转一圈，够用了。

消耗量算法：日限 180 分 ÷ 每组 10 分 × 每组 3 道 = 54 道/天；数学占 55%（生成器），
剩约 24 道由语文、英语均分 → **单科每天约 12 道**。

目标不变：**每个启用的 (科目, 年级) ≥ 150 道，一周内不撞同一道题**。
小学语文、英语已全部达标；**初中各科和科学还是占位数**，孩子升年级前要补。

### 策略：自编为主

题目由项目自己编写、随源码以 **Apache-2.0** 发布（与项目许可一致，`bank.json` 元信息里写明）。不走「灌别人的库」这条路，三个理由：

1. **许可**：第三方数据能不能用，取决于上传者有没有权利授权，MIT / Apache 也解决不了
   「他到底有没有权给」。不打包就没有这个包袱。
2. **体积**：几个大源的题都塞在 GB 级 Release 包里（带音频、插图），抽题库还得另写脚本。
3. **质量**：教材配套题大量依赖插图、短文、上下句，电视上根本答不了，清洗成本比自编还高。

仓库只提供工具和格式，谁想用第三方源就自己下载、自己转（见 [QUIZ_FORMAT.md](QUIZ_FORMAT.md)）。
出了问题也只影响他那一份，不会污染整个项目。

### 自编题规范

写成规范是为了批量编题时不用每题重新想，也是为了孩子做题时不至于被题目的毛病带偏。

1. **一题一个知识点**，`knowledge` 字段写具体（拼音 / 量词 / 字形 / 词义），错题加权靠它。
2. **选项 4 个，同一范畴、长度相近**。问「哪个是水果」，干扰项就得是别的水果或蔬菜，
   不能是「桌子」「铅笔」——那不用想也知道。
3. **不用「以上都对 / 以上都不对」**，也不用否定式提问（「下列哪个不是」），孩子容易看漏。
4. **题干 ≤ 26 字，选项 ≤ 16 字**。超了电视上会折行；硬上限是 60 / 30，工具直接丢。
5. **不依赖图片和上下文**，不出现「如图」「阅读短文」「根据材料」。
6. **解析写「为什么这个对、那个错」**，一句话，别写「选 A」——重排选项后会对不上号
   （工具检测到这种写法会跳过该题不重排）。
7. **正确答案别总放第一格**。见下节。
8. 数学不用编，有生成器；要加也是加生成器的题型。

### 已经踩过的坑：答案几乎全在 A

第一次体检发现 **120 道题里 128 个答案是 A（96%）**，等于孩子一路按左键就能过，
门禁形同虚设。原因很简单：手写题时「正确项放第一个」是最省事的写法。

已用 `tools/import_bank.py rebalance` 打散：按 (科目, 年级) 分桶，
保留正确选项内容、只改它站哪一格，重排后分布 31% / 28% / 23% / 18%。
校验过 120 道老题的正确项内容零变化（86 道挪了位置）。

`check` 现在会打印答案分布，任一项超过 45% 就告警。**以后每批新题编完都要跑一次 rebalance。**

### 编题工作流（工具已完成）

**批量生成**（推荐，改 `tools/data/*.py` 的字表/词表再重跑）：

```bash
python tools/gen_bank.py -o tmp/gen.json          # 生成（默认同 seed 可复现）
python tools/import_bank.py rebalance tmp/gen.json
python tools/import_bank.py merge app/src/main/assets/quiz/bank.json tmp/gen.json \
    -o app/src/main/assets/quiz/bank.json
python tools/import_bank.py check app/src/main/assets/quiz/bank.json
```

**手编少量题**（Excel/WPS 表格路线）：

```bash
# 1. 导出成表格
python tools/import_bank.py export app/src/main/assets/quiz/bank.json -o 题库.csv
# 2. 在 Excel / WPS 里加题（每行一道，格式见 QUIZ_FORMAT.md）
# 3. 转回 JSON
python tools/import_bank.py convert 题库.csv -o tmp/new.json --source 自编 --license "Apache-2.0"
# 4. 打散答案位置
python tools/import_bank.py rebalance tmp/new.json
# 5. 合并进题库（自动去重、接着编号）
python tools/import_bank.py merge app/src/main/assets/quiz/bank.json tmp/new.json \
    -o app/src/main/assets/quiz/bank.json
# 6. 体检
python tools/import_bank.py check app/src/main/assets/quiz/bank.json
```

工具还会拦下这些：选项超过 4 项、答案不在范围内、题干超 60 字、含「如图/阅读短文」、
科目不在白名单、年级越界、题干归一化后重复。规则表和阈值理由见 [QUIZ_FORMAT.md](QUIZ_FORMAT.md) 第 5 节。

### 家长端「题库管理」功能（2.7.9 已实现）

**实现结果**：没有走 U 盘和「电视上填 URL」这两条路——TV 上输入地址和选文件都难用。
改成了「电视开服务、手机浏览器操作」：

- 入口：家长设置 → 答题门禁 → 「手机配置题库」，开关式开启，地址直接显示在电视上
- 手机端：上传 JSON / CSV、粘贴文本、看统计、导出、清空、改答题参数、远程试答
- 存储：`filesDir/custom_bank.json`，与 assets 合并，**同 id 自定义覆盖内置**（原设计是整体替换，改成覆盖更实用：既能加题，也能改掉某道内置题）
- 校验：逐题校验并返回题号 + 原因，好题照常入库（原设计要求「失败原样保留旧库」，改为「逐题拒绝、不整库失败」，家长一次导 1000 道不会因为 1 道错题全废）
- 生效：写盘后 `QuestionBank.invalidate()`，下一次抽题就用新库，不用重启
- 实现：`net/ConfigServer.kt` + `quiz/BankStore.kt` + `assets/web/index.html`

以下是最初的设计记录，留作参考：

**入口**：家长设置 → 「题库管理」（放在答题门禁页底部，或家长首页独立卡片）

**信息展示**（只读部分）

## P1.5 · 待做功能（v2.9.0 之后，按性价比排序）

六条都已评估过可行性与代价，代码位置写在「落点」里。前三条改动小、收益直接，
建议按这个顺序做；后三条涉及 UI 流程，最好一次想清楚再动。

### 1. 到点直接待机（防切 HDMI / 机顶盒绕过）

**动机**：现在额度用尽只挡「受限应用」。孩子把信号源切到 HDMI、有线电视或机顶盒，
限制就完全失效了。产品叫「电视时间管家」，家长预期是「电视到点不能看」，
不是「某个 App 到点不能用」——这是目前最大的绕过口子。

**约束**：
- `force-lock` 靠设备管理员，TCL 这类固件会定期撤销，撤销后 `lockNow()` 是空操作
  （`lockDevice()` 已返回 false）。待机失败要降级成「暂停播放 + 全屏遮罩」，并记事件日志。
- 待机后按一下开机键就能唤醒，所以**不能把关屏当唯一手段**：唤醒后必须仍在锁定态。
- 不能误伤：家长自己在看电视、半夜待机都不能触发。只在「额度耗尽 + 当前档案不是家长」时执行。

**落点**：`TimeTrackingService.startSleepCountdown()` 已有 10 秒倒计时与 `lockNow()`；
把触发条件从「前台是受限应用」放开到「额度耗尽」，并在 `ACTION_SCREEN_ON` 时补一次遮罩
（`startOverlayHeartbeat()` 里已有自愈逻辑，可复用为检查点）。

**验收**：额度用尽 → 10 秒后待机（管理员有效时）；按开机键唤醒 → 3 秒内重新被挡；
切到 HDMI 再切回应用 → 仍被挡；家长档案下不待机。

### 2. 配置一键备份 / 恢复

**动机**：换电视、恢复出厂、重装都得重新配额度、作息、题库、错题、密码。现在只能导题库，
家长最容易丢的恰恰是「好不容易配好的作息和限额」。

**范围**：`HouseRules` 全部 prefs、`files/bank.json`、错题统计、答题设置、家长 PIN。
**不含**用量历史（体积大，换机后没有意义）。

**约束**：
- 备份文件里含 PIN，导出时要明确提示「这是敏感文件，别发群里」；不做加密
  （家长记不住第二个密码，反而会丢数据）。
- 导入必须校验 `schemaVersion`；不认识的字段忽略而不是报错。**绝不能重演题库那次
  「解析成功但 0 条」把数据清空**——导入前后都要能回滚（先写 tmp，成功后 rename）。
- 只走手机网页下载/上传。电视端 SAF 选文件对家长太麻烦，不做。

**落点**：新增 `GET /api/backup`、`POST /api/restore`，聚合逻辑放 `data/Backup.kt`。

**验收**：A 电视导出 → B 电视全新安装后导入 → 额度/作息/题库题数/错题条数/PIN 全部一致；
导入损坏文件 → 明确报错且原数据一字不变。

### 3. 答题奖励时长（把「罚款」变成「激励」）

**动机**：现在答对只是「放行本次」，孩子体验上等于罚款。改成「答对一组奖励 10 分钟」，
门禁就变成了激励，孩子有动力认真答而不是乱点。

**约束**：
- **必须有每日奖励上限**（建议默认 30 分钟），否则孩子坐在电视前一直刷题就能无限看。
- 奖励只加「今天」，与 `addExtraToday()` 现有的 240 分钟封顶共用，不另开一套计数。
- 家长可关（默认关，避免升级后行为突变）。
- 奖励要进事件日志，否则家长看到额度莫名多了会以为是 bug。

**落点**：`quiz/QuizSettings.kt` 加 `rewardMinutes` / `rewardCap`；`service/QuizGate.kt` 的
`onPassed` 里调 `HouseRules.addExtraToday()`；日志 `quiz_reward`。

**验收**：答对一组 +10 分钟且屏幕上的剩余时间同步；拿到上限后提示「今天的奖励拿满了」
且不再增加；家长关闭后行为回到现在。

### 4. 多档案（二孩家庭）

**动机**：`profile` 表本来就有，但只预置「儿童 / 家长」两条。二孩家庭现在只能共用一份额度，
或者每天改设置。

**范围**：新增 / 重命名 / 删除档案；每个档案独立的每日额度、单次额度、受限应用列表。
电视上切换继续走 `ProfileSelectionActivity`。

**约束**：
- 家长档案不允许删除或改名（PIN 校验逻辑依赖它）。
- **切换档案必须过 PIN**，否则孩子自己切到一个「没设限额的档案」就绕过去了。
- 删除档案时问清楚：历史用量一起删还是保留（`UsageLog.profileId` 已隔离，技术上两种都行）。

**验收**：新建「妹妹」设 20 分钟 → 切过去额度独立；切回「儿童」额度不受影响；
家长档案没有删除入口；删除普通档案后不会留下孤儿 `UsageLog` 拖慢报表。

### 5. 加时申请审批

**动机**：孩子看到一半被挡，家长不在电视旁。现在只能家长掏手机进配置页手动加时，
孩子完全不知道能不能等，通常会反复按遥控器或者直接关电视。

**流程**：遮罩上加「申请再看 15 分钟」→ 写一条 pending 请求（当天限 3 次）→
手机网页 `/api/requests` 列出待批请求 → 家长点批准/拒绝 → 批准即 `addExtraToday(15)`，
电视端轮询到结果后自动放行。

**约束**：
- 不做推送（没有服务器，也不想引入）。家长得主动打开网页——这一点要在电视端说清楚，
  不能让孩子以为「点了就通过」。
- 请求存 prefs，0 点清空；同日超过 3 次直接拒绝并提示。
- 电视端要有三态反馈：等待中 / 已批准 / 被拒绝（被拒绝时说明「家长不同意」而不是静默）。

**验收**：申请后手机端 5 秒内可见；批准后电视 30 秒内自动放行；第 4 次申请被拒；
跨 0 点后计数归零。

### 6. 错题难度自适应

**动机**：现在错题只影响「下次出现概率」（`QuizStats` 的权重写死）。低年级孩子卡在同一个
知识点上会一直答错，越答越挫败，最后变成乱点。

**做法**：连续答错 2 次 → 该科目下一次出题降一档（同科目低一年级，最低到一年级）；
连续答对 3 次恢复原年级。降档只在「本轮」生效，不改家长设置。

**约束**：
- 不能降到无题可出：题库空档格（比如一年级没有英语）就保持原年级，不能抛异常。
- 降档要记事件日志，家长在周报里能看出「孩子被降档了」，否则会以为设置没生效。

**验收**：连错 2 题后下一题年级 -1；连对 3 题恢复；一年级连错时仍出一年级题且不崩。
